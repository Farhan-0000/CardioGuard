# MedBridge knowledge-base corpus (`data/`)

The knowledge base is a **curated** set of 27 authoritative documents on
hypertension and cardiovascular care. Nothing is scraped: a document is in the
index only if it is listed in [`corpus_manifest.json`](corpus_manifest.json),
with its issuing organisation, year, canonical URL, licence (as stated by the
publisher), topic tags and the SHA-256 of the exact file that was indexed.
This is the defence against RAG poisoning that the specification asks for:
only clinical societies, government health bodies and peer-reviewed
statements/reviews, versioned by hash.

| Type | Documents | Sources |
|---|---|---|
| Guideline (PDF) | 13 | AHA/ACC 2025, ESC 2024, ISH 2020, WHO 2021 + HEARTS (2), KDIGO 2021, NICE NG136 / NG133 / NG106 / NG196 / NG238 / NG185 |
| Guideline (HTML, PubMed Central) | 3 | ACC/AHA atrial fibrillation 2023, ACC/AHA primary prevention 2019, AHA/ACC cholesterol 2018 (executive summary) |
| Statement / review (HTML, PubMed Central) | 4 | AHA BP-measurement statement 2019, AHA resistant-hypertension statement 2018, ESC Council on Hypertension position on hypertensive emergencies 2019, Clinical Cardiology review of the 2023 chronic coronary disease guideline |
| Patient information (HTML) | 7 | MedlinePlus (high BP, heart failure, AFib, cholesterol, heart attack), NHLBI (high BP, high-BP treatment) |

Per-document page/chunk counts and topic coverage: [`reports/corpus_stats.md`](../reports/corpus_stats.md)
(regenerate with `python -m medbridge.ingestion --stats`).

## Getting the files

`data/*` is git-ignored except this README and the manifest, because several
publishers do not allow redistribution. On a fresh clone:

```bash
python scripts/download_corpus.py        # downloads what can be fetched, verifies SHA-256
python scripts/download_corpus.py --verify-only
python -m medbridge.ingestion --recreate # parse, chunk, embed and index (≈3 min on an M-series CPU)
python -m medbridge.ingestion --stats    # tables + figure for the report
```

Files marked `"volatile": true` in the manifest are regenerated by the
publisher on every download (NICE PDFs carry the download date, journal PDFs a
"Downloaded from … on <date>" watermark, web pages change markup), so a freshly
downloaded copy will not match the recorded hash. The downloader reports this
as `drift`; incremental ingestion then re-indexes the document automatically.

## Manual downloads

These files could not be fetched by script because the publisher site serves a
browser check (Cloudflare / proof-of-work) to non-browser clients. Download
them in a normal browser and save them at the path given:

### Deliberately excluded

* **ADA Standards of Care in Diabetes—2026, §10 Cardiovascular Disease and
  Risk Management** (PMC12690187). Its licence states that it "may not be
  reproduced, distributed, or used for text or data mining, machine learning,
  or similar technologies without prior written permission", so it is not
  indexed. Diabetes is covered by the WHO HEARTS protocols, NICE NG136/NG238,
  KDIGO 2021 and the ACC/AHA prevention and cholesterol guidelines.
* **PubMed-wide article collections** — never scraped (RAG-poisoning risk).

## Licence notes (read before sharing anything)

* **Open licences:** WHO documents (CC BY-NC-SA 3.0 IGO), KDIGO 2021
  (CC BY-NC-ND 4.0), the Clinical Cardiology review (CC BY 4.0),
  MedlinePlus health-topic summaries and NHLBI pages (US Government, public
  domain).
* **Free to read, not redistributable:** AHA/ACC guidelines and statements
  (publisher PDFs and PMC author manuscripts), ISH 2020, ESC position paper,
  NICE guidelines (subject to the NICE Notice of rights). They are used for
  local, non-commercial academic indexing only and are never committed.
* **ESC 2024 hypertension guideline (`ESC_HTN_2024`)** — retained from the
  original three-document corpus. Its copyright page states that ESC/OUP
  reserve text-and-data-mining and AI-training rights (EU Directive 2019/790
  Art. 4(3) opt-out) and that no part may be "stored in a retrieval system"
  without permission. Keeping it in the index is a team decision for this
  academic prototype; to drop it, delete its manifest entry and run
  `python -m medbridge.ingestion --prune`.

## Retrieval evaluation set

[`evaluation/datasets/retrieval_eval_v1.json`](../evaluation/datasets/retrieval_eval_v1.json)
(70 queries, 26 lay / 44 clinical, all 13 topics) was labelled by regex search
over the parsed document text — never with the MedBridge retriever. A
retrieved chunk is relevant when its `guideline_id` matches and its
`[page_number, page_end]` overlaps a labelled page.
