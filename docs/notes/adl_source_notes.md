# ADL source notes (from work-stream reports, 2026-10-09/10)

- [E — ChatGPT/Claude-style web SPA + admin dashboard (FastAPI-] SPA served by FastAPI without a build step: medbridge.web.mount_web(app) serves `/` (index.html), `/dashboard` (dashboard.html) and `/static/*` through a StaticFiles subclass limited to css/js/img. Content types are explicit and platform-independent (Windows can map .js to text/plain, which breaks ES modules), and caching is short max-age plus ETag/304 revalidation. HTML is no-cache. The UI is plain HTML/CSS/ES modules with no Node or bundler at runtime; Node is used only for optional unit tests. This keeps a single-process, local-only deployment on the Windows demo laptop. It preserves the architecture because the presentation layer only talks HTTP to the existing API and holds no clinical or AI logic.

- [E — ChatGPT/Claude-style web SPA + admin dashboard (FastAPI-] No third-party JS, own escape-first Markdown renderer, strict CSP: the CSP is default-src 'self'; script-src 'self' with no inline scripts, handlers or eval, and was verified against the production middleware header on the real backend. The renderer escapes all text first and only adds markup it controls. Links are http/https only (URL-parsed, rel=noopener noreferrer); citation markers become buttons. The only innerHTML writes take renderer output, which test_web_static.py enforces. Node tests cover XSS payloads (img onerror, script, svg onload, javascript:/data:/vbscript: links, attribute break-out, NUL placeholder forgery, deep nesting, pathological input). This replaces the brief's suggestion of vendored marked + DOMPurify, following the owner's no-download decision.

- [E — ChatGPT/Claude-style web SPA + admin dashboard (FastAPI-] Client-side conversation list, so the server stores no titles: localStorage holds [{id, token, title (first 48 characters of the first message), createdAt, updatedAt}] plus theme, mode and consent, with in-memory fallback when storage is blocked. The server stores only encrypted turn data. Delete and 'Clear my data' call DELETE /api/sessions/{id} (crypto-shred) before removing the local entry, so erasure is server-side. Trade-off: the token in localStorage is reachable by same-origin scripts, which is mitigated by the CSP and escape-first rendering. The admin token goes in sessionStorage.

- [E — ChatGPT/Claude-style web SPA + admin dashboard (FastAPI-] SSE consumption: POST + fetch + ReadableStream with an own parser, because EventSource supports only GET. It is CRLF-split safe, joins multi-line data and skips comments. stage events drive a live stepper from STAGE_LABELS (skipped stages greyed); meta, token and done finalise the full MessageResponse. If the stream fails before any event, the client falls back to the non-streaming endpoint. An `error` event is followed by the server's safe `done`. Stop aborts only the client fetch; the server shields and persists the turn, so routing semantics and the never-throw guarantee are unchanged.

- [E — ChatGPT/Claude-style web SPA + admin dashboard (FastAPI-] 'Why this answer?' explanation panel: renders MessageResponse.explanation as a decision path (Emergency → Gate 1 → Evidence → Gate 2 → Final), separate Gate 1 and Gate 2 cards (decision, source such as llm/fallback/loop_breaker/fastpath/calibrated, rationale, missing fields, votes/features), the top-5 reranked evidence with relevance bars and cited markers, Gate 3, emergency rules, citation validation and per-stage latency bars. Hidden behind a toggle in patient mode, expanded in clinician mode. It is purely presentational: it shows the two gates as separate decision points and never recomputes or overrides a decision. The only client-side domain logic is a BP-category display fallback that mirrors the server thresholds.

- [E — ChatGPT/Claude-style web SPA + admin dashboard (FastAPI-] Streamlit kept as a legacy fallback: medbridge/frontend still works against the new API. It captures session_token, sends Authorization: Bearer, keeps the token out of the URL, and starts a new session and resends once on 401/403/404. Welcome and sidebar text now match the indexed corpus, and no web fonts are loaded. This gives a second HTTP-only client for demos and backwards compatibility without touching the backend.

- [G2 — MedBridge-HalluBench v1 dataset (synthetic)] Decision: HalluBench v1 is fully synthetic (ADL-017). It has 247 items over 6 categories, mirroring the five-action routing semantics, with a gold action and an explicit acceptable-action list per turn. Rationale: it measures both gates as separate decision points. Gate 1 is tested by the SOFT-ASK first turns and the loop-breaker items at threshold 2. Gate 2 is tested by the ANSWER, GENERALIZE and ABSTAIN distinctions. The deterministic fast path is tested by the ESCALATE items. The architecture is unchanged; this is evaluation data only.

- [G2 — MedBridge-HalluBench v1 dataset (synthetic)] Decision: gold evidence was labelled by regex over the parsed corpus text, never by the MedBridge retriever, and page numbering matches the index payload. Rationale: this avoids biasing the evaluation toward the system under test and lets judges and retrieval metrics use the labels directly. All 120 cited pages were verified by regex and are covered by indexed chunks.

- [G2 — MedBridge-HalluBench v1 dataset (synthetic)] Decision: lenient acceptable sets are ANSWER/GENERALIZE for answerable items and ABSTAIN/GENERALIZE for most unanswerable items. Paediatric and pregnancy dosing items and out-of-domain items accept ABSTAIN only, and emergency turns accept ESCALATE only. Rationale: neighbouring actions count as equally safe only where a general answer cannot leak unsupported specifics.

- [G2 — MedBridge-HalluBench v1 dataset (synthetic)] Decision: the dev/test split is stratified by category with seed 42 and dev fraction 0.2. Dev (49 items) is for calibration only (NLI threshold, V1 threshold, V2 tau) and all results are reported on test (198 items). Rationale: the protocol requires a held-out split and forbids tuning on test.

- [G2 — MedBridge-HalluBench v1 dataset (synthetic)] Decision: items that paraphrase the gate prompts' few-shot examples are tagged `prompt_overlap` (14 items) rather than removed. Rationale: the brief's own examples (Cardiozepam, the beta-blocker 'cure' premise, facial droop) coincide with those few-shots; tagging keeps them for completeness while allowing a contamination-free sensitivity analysis.

- [WS-A — core pipeline, retrieval, message/health/metrics/conf] Orchestrator decomposition + single persistence. Decision: replace the 540-line `_execute_pipeline` with stage methods over a `TurnContext` (privacy → emergency → load_state → small_talk → extraction → context_gate → retrieval/rerank → evidence_gate → generation → verification → persistence), and replace 5+ flushes per turn with one `turn_store.persist_turn` call. Rationale: testability (each stage and fallback is unit tested in isolation), per-stage tracing, fewer DB round-trips, and an atomic turn. Why the architecture is preserved: same stage order and routing semantics; both gates remain separate decision points; spec fallbacks unchanged (Gate 1 → PROCEED, Gate 2 → GENERALIZE, generator → template); never-throw top-level guard; clinical_events and audit_logs stay append-only (only the store writes).

- [WS-A — core pipeline, retrieval, message/health/metrics/conf] Speculative retrieval (ADL-027). Decision: when SPECULATIVE_RETRIEVAL is on and Gate 1 is active, retrieval is started as a task right after extraction (it only needs the extractor's search query) and runs during Gate 1. SOFT-ASK below the threshold cancels the task, and the results never reach Gate 2 or the generator (recorded as discarded). PROCEED or loop-breaker awaits it, recording overlap as saved_ms. Rationale: one live turn saved 1,210 ms (all of Gate 1's time). Why the architecture is preserved: Gate 1 alone decides whether the evidence is used; unit tests prove SOFT-ASK discards the results, PROCEED uses them, and output is identical with the flag on or off.

- [WS-A — core pipeline, retrieval, message/health/metrics/conf] Citation validation and ANSWER→GENERALIZE downgrade (ADL-028). Decision: `[n]` maps to the n-th chunk given to the generator; invalid markers are stripped; markers are renumbered by first appearance; citations are rebuilt from chunk metadata (source 'ORG YEAR', section, page, URL, first ~350 chars); LLM-written excerpts are never trusted. If CITATION_VALIDATION_ENABLED and an ANSWER (with the Evidence Gate active) has 0 valid citations, it is relabelled GENERALIZE. Rationale: the 'zero uncited clinical claims' rule; fabricated markers and excerpts are a hallucination channel. Why the architecture is preserved: a post-generation check that can only lower the action; the gate decision stays in the audit log (gate_2 = ANSWER, final = GENERALIZE).

- [WS-A — core pipeline, retrieval, message/health/metrics/conf] Small-talk handling (ADL-029). Decision: after the emergency fast-path, a deterministic, conservative detector (whole-message match, ≤8 words / 60 chars, no digits or clinical vocabulary, never 'yes'/'no') answers greetings, thanks, goodbyes, 'who are you' and acknowledgements with fixed claim-free templates under action GENERALIZE. Gates are recorded with source 'rule'; no LLM call; the loop-breaker counter is unchanged. Rationale: removes 4 LLM calls and an ABSTAIN that reads as a refusal to say hello (live: 13 ms instead of ~15 s). Why the architecture is preserved: no new action; uses the existing GENERALIZE semantics with no clinical content; any clinical or ambiguous message still goes through both gates; emergencies are caught earlier.

- [WS-A — core pipeline, retrieval, message/health/metrics/conf] Gate 3 integration (V2). Decision: when enabled (ablation V2/V12 or GROUNDING_VERIFIER_ENABLED), the grounding verifier checks the ANSWER/GENERALIZE draft against the chunks given to the generator. At or below τ (GROUNDING_MAX_UNSUPPORTED_FRACTION), unsupported claim sentences are removed and citations re-validated. Above τ, an ANSWER is regenerated once as GENERALIZE and re-verified, becoming ABSTAIN if still above τ; a GENERALIZE above τ becomes ABSTAIN. A verifier failure keeps the draft and records the failure. Rationale: the §6.7 fallback variant (V2) for the hallucination study. Why the architecture is preserved: it is added after the dual gate and never replaces it; it can only make the response more conservative; ABSTAIN still uses the template.

- [WS-A — core pipeline, retrieval, message/health/metrics/conf] Warm-up and readiness. Decision: the lifespan starts a background task calling `PipelineOrchestrator.warmup()`, which loads the dense and sparse embedders, probes Qdrant, loads the reranker, and loads the gate/generator models in Ollama with keep_alive (plus the NLI verifier when enabled). The retrieval and LLM sides run concurrently; flags go to app.state.readiness and /health reports degraded until warm. Rationale: the Review-3 cold-start latencies; reranker model load alone measured ~4.4 s. Real warm-up took 4.6 s; afterwards hybrid retrieval took 13 ms and rerank of 20 chunks 141 ms. Why the architecture is preserved: no change to the request path, only when models load; the app still serves (lazily) if warm-up fails.

- [WS-A — core pipeline, retrieval, message/health/metrics/conf] Caches. Decision: an in-process, thread-safe LRU cache of query embeddings (RETRIEVAL_CACHE_SIZE) in EmbeddingClient, with the dense and sparse encoders run concurrently via asyncio.gather + to_thread; and an LRU + TTL cache of fused results keyed by (query, top_k, mode) in HybridRetriever, with empty or failed results not cached. Rationale: repeated queries, regenerations and evaluation reruns cost nothing (a cached retrieval took 0.01 ms). Why the architecture is preserved: the cache returns exactly what the same Qdrant search would; the TTL picks up re-indexing; retrieval stays read-only.

- [WS-A — core pipeline, retrieval, message/health/metrics/conf] RRF k=60 made explicit (bug fix). Decision: use `RrfQuery(rrf=Rrf(k=60))` instead of `FusionQuery(RRF)`. Rationale: Qdrant's un-parameterised RRF uses k=2 (measured: a document ranked first in both lists scores 1.0 with the default and 2/60 with k=60), so the documented 'RRF(k=60)' was not actually implemented. Why the architecture is preserved: it now matches the specified retrieval design exactly.

- [WS-A — core pipeline, retrieval, message/health/metrics/conf] SSE streaming. Decision: POST /messages/stream and /regenerate?stream=true run the orchestrator in a task with its own DB session (committed at the end) and an on_event → asyncio.Queue bridge. They emit live `stage` events, then `meta`, then `token` word-groups (~12 ms apart; a typewriter effect because the generator returns validated JSON), then `done` with the full MessageResponse; on failure `error` then a safe `done`. Headers: Cache-Control no-cache, X-Accel-Buffering no. A client disconnect does not stop the turn (it still completes and persists). Rationale: perceived latency and visible progress through the gates. Why the architecture is preserved: the identical orchestrator call as the JSON route; text is only streamed after validation (and Gate 3), so nothing unvalidated reaches the patient.

- [WS-A — core pipeline, retrieval, message/health/metrics/conf] Privacy stage ordering. Decision: redact first and use the redacted text for every LLM call, retrieval, log line and persisted row. The deterministic emergency classifier alone sees the raw text (higher recall; it is never persisted or logged). Redaction failure fails closed. Why the architecture is preserved: the emergency fast-path still runs before any LLM call; the XML isolation of untrusted input is unchanged inside the AI layer.

- [WS-A — core pipeline, retrieval, message/health/metrics/conf] Reranker device. Decision: pick the device automatically (cuda, then mps, then cpu), keep calls in to_thread, and serialise predict with a lock. Measured on M5 for 20 synthetic pairs, warm: MPS 45 ms median vs CPU 118 ms. Why the architecture is preserved: same cross-encoder and top-20 → top-5; Constitution §7.7 thread offloading kept.

- [WS-B — AI layer (LLM wrapper, prompts, generator modes, V1 c] Native Ollama API with structured outputs, think control and keep_alive. Decision: call POST /api/chat with `format` = a grammar-ready JSON schema of the output model, options {temperature, seed, num_ctx, num_predict, top_p}, keep_alive, and `think` sent only to models whose /api/show capabilities include thinking. Rationale: grammar-constrained decoding makes small local models emit valid, complete JSON (8/8 live calls parsed on the first attempt). Rationale-first field order lets the gates reason before deciding. Thinking off saves latency. keep_alive plus warm-up avoids the cold loads seen in Review 3. Architecture: unchanged. Gates still run at temperature 0.0 / seed 42 with top_p 1.0; the generator runs at 0.3 with top_p 0.95 and the same seed for reproducible evaluation. Retry, repair and the None → spec-fallback contract are kept.

- [WS-B — AI layer (LLM wrapper, prompts, generator modes, V1 c] Per-role models. Decision: every call carries an explicit `model`; the extractor and both gates use settings.gates_model, the generator uses settings.generator_model, and both fall back to LLM_MODEL. Rationale: a smaller, faster model can make the classification decisions while a stronger one writes the answer, which suits the 6 GB RTX 4050. Architecture: the same four LLM calls in the same order; only the weights behind them can differ.

- [WS-B — AI layer (LLM wrapper, prompts, generator modes, V1 c] LOCAL_ONLY_MODE. Decision: when true (the default), the wrapper builds only the Ollama provider, logs an error if LLM_PROVIDER names a remote provider, refuses remote sends at send time as a second guard, and warns if the Ollama host is not loopback. Groq/OpenAI stay available as optional providers only when local-only is switched off. Rationale: a guarantee that no patient text leaves the machine (constitution §8.3, brief §2). Architecture: all traffic still passes through the single ResilientLLMWrapper.

- [WS-B — AI layer (LLM wrapper, prompts, generator modes, V1 c] Prompt redesign. Decision: the scope widened to cardiology centred on hypertension. Few-shot examples were added: 3 for the extractor, 8 for Gate 1, 7 for Gate 2. Gate 2 now has explicit ordered rules for out-of-domain questions, drugs/treatments absent from the evidence (possibly fabricated), dose/regimen/number questions the evidence does not state, paediatric dosing, pregnancy decisions, false premises (GENERALIZE so the answer corrects them) and missed emergencies (ESCALATE). Gate 1 asks only for facts needed for safe personalised advice, uses a fixed 12-field vocabulary, and lets general, out-of-domain, fabricated-drug and false-premise questions through to Gate 2. The generator is patient-friendly markdown that never invents numbers or drugs, corrects false premises, and never prescribes; SOFT-ASK asks for the specific missing fields and makes no clinical claims. Architecture: both gates remain separate decision points with the same outputs. Gate 1 still decides SOFT-ASK vs PROCEED before retrieval; Gate 2 still decides among four actions after retrieval. Patient text, including earlier patient turns, stays inside <untrusted_user_input>, and tag-like text is escaped so injected input cannot close the XML blocks.

- [WS-B — AI layer (LLM wrapper, prompts, generator modes, V1 c] Index-based citations. Decision: chunks are rendered as <chunk index="n" source="ORG YEAR — title" section page> and the model cites [n]; it no longer generates citation objects (ResponseGeneratorOutput.citations is excluded from the format schema), and the server rebuilds citations from the markers. Rationale: small models copy chunk ids and URLs badly; a single index is reliable, shorter, and easy to validate or strip in core/citations.py. Architecture: grounded generation with inline citations, as before; the ANSWER-with-zero-valid-citations → GENERALIZE downgrade can still apply.

- [WS-B — AI layer (LLM wrapper, prompts, generator modes, V1 c] V1 design: calibrated Evidence Gate. Decision: run Gate 2 once per distinct deterministic evidence ordering (original, reversed, rotate-by-k), each at temperature 0.0 / seed 42; take the majority, with ties going to the more conservative action (ESCALATE > ABSTAIN > GENERALIZE > ANSWER). Then apply quantitative thresholds through the pure decide_with_thresholds rule, which is shared with evaluation/calibrate.py: ANSWER with low max_rerank or low entity coverage becomes GENERALIZE; ANSWER/GENERALIZE with irrelevant evidence becomes ABSTAIN; ESCALATE is never overridden and ABSTAIN never upgraded. If every vote fails, GENERALIZE (spec fallback). Rationale: self-consistency normally needs sampling. Here the variation comes from LLM position sensitivity to evidence order, so the zero-temperature invariant is kept while order-induced errors are averaged out. The reranker and entity-coverage signals add an evidence-sufficiency check the LLM cannot override toward a less safe action. Architecture: same position and the same four outputs as Gate 2; the system can only become more conservative.

- [WS-B — AI layer (LLM wrapper, prompts, generator modes, V1 c] V2 design: Grounding Verifier (Gate 3). Decision: after generation and before the patient sees the draft, split it into sentences, skip non-claims, and NLI-check each claim with a local cross-encoder against the chunks it cites ([n]), or all chunks if uncited, using windows of about 3 sentences. Remove unsupported claims while keeping the markdown, and report unsupported_fraction; the orchestrator keeps, downgrades or abstains. Inference runs in a worker thread on cuda > mps > cpu. The production NLI model (cross-encoder/nli-MiniLM2-L6-H768) is deliberately different from the evaluation NLI judge, so the verifier is not graded by the same model it uses to verify. Architecture: an added third gate that can only remove content or make the response more conservative; Gates 1 and 2 are untouched, and if the model is unavailable the draft is returned unchanged.

- [WS-B — AI layer (LLM wrapper, prompts, generator modes, V1 c] Drug normalisation. Decision: deterministic brand → generic mapping (189 brands, 65 of them Indian, 94 generic classes) that ignores case, hyphens, strengths, salt names and release suffixes, with difflib fuzzy matching at ≥ 0.88 for names of 5+ characters. It is applied after extraction to MEDICATION_ADDED/STOPPED (canonical generic name, with brand_name and drug_class kept) and in query expansion. Rationale: patients say 'Telma 40' while guidelines say 'telmisartan'; one canonical name lets the state de-duplicate brand and generic mentions and lets retrieval match the guidelines (addresses RABBITS brand/generic consistency). Architecture: a pure post-processing step on the extractor output; the snapshot is still produced only by the deterministic projector folding the events.

- [WS-B — AI layer (LLM wrapper, prompts, generator modes, V1 c] Query expansion. Decision: deterministic, additive, duplicate-free, length-bounded expansion of the search query: lay terms → clinical synonyms (water pill → thiazide diuretic, blood thinner → anticoagulant, racing heart → atrial fibrillation, and so on) plus generic names and classes of any brands mentioned in the query or the message. Rationale: the BM25 and dense retrievers both match guideline wording better, and the original query text is preserved. Architecture: it changes only the query string fed to the unchanged dense+sparse → RRF(k=60) → cross-encoder retrieval pipeline.

- [WS-B — AI layer (LLM wrapper, prompts, generator modes, V1 c] Request cache for evaluation. Decision: set_request_cache(cache) installs an object with get(key)/set(key, value). The key is the sha256 of the canonical provider request payload, excluding keep_alive. On a hit the stored raw reply is validated and returned without an HTTP call (LLMCallStat.cached=True); only replies that parsed and validated are stored. It is off in production. Rationale: across the C0–C5/V1/V2 conditions many LLM requests are byte-identical, so memoising them makes paired conditions differ only in pipeline structure and saves hours of local GPU time. Architecture: identical outputs for identical inputs, which follows from the deterministic temperature-0 / seed-42 setting.

- [WS-C emergency (deterministic natural-language emergency cla] Decision: the emergency fast-path stays a single deterministic rules engine (regex compiled at import time plus dictionary look-ups) and now understands colloquial phrasing, negation, typos and context. Steps: normalise, extract BP readings, match 26 rule ids, then filter per clause. `classify()` is unchanged; `classify_detailed()` explains every decision with rule ids, negated and suppressed ids, the decisive BP reading and evidence spans.

- [WS-C emergency (deterministic natural-language emergency cla] Why it keeps NON-NEGOTIABLE #1: no LLM, no network, no model and no randomness, so the same text always gives the same result (tested). A test parses the module's imports and requires stdlib plus medbridge.api.schemas.enums only. It still runs on the raw message before any LLM stage. Measured median for a 2,000-character message is about 1.2 ms (p95 1.25 ms; worst of 1,000 runs 3.1 ms); short messages take about 0.03–0.05 ms. Pathological 2,000-character repetitions stay at or below 2.2 ms median because clause-level checks are cached. The < 10 ms budget is enforced by tests.

- [WS-C emergency (deterministic natural-language emergency cla] Negation scope: a cue (no/not/never/without/denies/no longer/free of/n't + have/feel/get/want...) must come before the symptom in the same clause, within 80 characters, with no affirmation in between (pronouns, 'now', 'suddenly', 'but'...). Comma or 'and' lists stay negated only if the first negated item is a red flag ('no chest pain, SOB or fainting' is negated; 'no fever, chest pain' escalates). Also supported: answer-style post-negation ('chest pain? no'), pseudo-negations ('not sure', 'no relief'), negation voiders ('never had pain like this'), and filler words that cannot swallow 'not', 'no' or 'never'. A negated symptom never suppresses a BP crisis or another symptom that was stated outright.

- [WS-C emergency (deterministic natural-language emergency cla] Informational and historical suppression: only explicit educational question frames are suppressed ('what are the symptoms of', 'how do I recognise', 'what should I do if someone...', 'if I ever...'). This is cancelled by any first-person or present-time marker anywhere in the message. Historical mentions need an explicit anchor (in 2015, years ago, history of, used to, as a child, it turned out to be...) and no recency word in the same clause. Side-effect questions, personal conditionals and any concrete BP crisis value keep escalating (ambiguous, so recall first). The module docstring holds the decision table.

- [WS-C emergency (deterministic natural-language emergency cla] Typo normalisation: NFKC, unified apostrophes, letter runs collapsed to 2, 'b.p.' to bp, a fixed 97-entry misspelling map, and a pre-computed one-edit matcher (insert, delete, substitute or swap adjacent letters) for 48 red-flag keywords of 6+ letters. Real English words one edit away (painting, blurred, lightness, spurred...) are on a stop-list, so normalisation cannot invent a symptom. Normalisation is deterministic and has no side effects.

- [WS-D — privacy layer + encrypted persistence + session/featu] **PII redaction before LLM and persistence:** a deterministic regex/rule detector with typed placeholders, and DOB converted to `[AGE: N]`. The orchestrator redacts once at stage 0, before any LLM call or write; the emergency classifier still sees the raw text, so the fast-path is unchanged. Clinical values are protected by construction and checked on 90 clinically dense negatives (0 altered). No ML model, no network, ~0.03 ms per message. It changes no gate and no action, only what the gates and generator see.

- [WS-D — privacy layer + encrypted persistence + session/featu] **Envelope encryption:** the master key wraps one Fernet data key per session (`session_keys`). Message text, audit text and rationales, event payloads, the snapshot and feedback comments are encrypted. Actions, chunk ids, latency and a PHI-free trace stay in plaintext for metrics. Readers decrypt transparently and accept legacy plaintext. The ORM schema and the event-sourcing projection are unchanged: the snapshot is still a pure fold over the events, just stored encrypted.

- [WS-D — privacy layer + encrypted persistence + session/featu] **Crypto-shredding keeps the append-only invariant:** right to erasure deletes only the wrapped key plus mutable rows (`message_history`, `context_snapshots`, `feedback`) and stamps `sessions.erased_at`. `clinical_events` and `audit_logs` are never updated or deleted (their rules are untouched and re-verified by tests), but their ciphertext becomes unreadable. Sessions are never deleted, because the foreign keys from the rule-protected tables would cascade into them.

- [WS-D — privacy layer + encrypted persistence + session/featu] **Signed session tokens:** HMAC-SHA256 `v1.payload.sig`, bound to one session id, with expiry (`SESSION_TOKEN_TTL_SECONDS`) and constant-time comparison. Every `/api/sessions/{id}/*` route requires one when `AUTH_REQUIRED` (missing → 401, wrong/expired → 403), replacing "knowing the UUID is enough". This is an access-control layer in front of the API and does not touch the pipeline.

- [WS-D — privacy layer + encrypted persistence + session/featu] **Admin auth:** the dashboard is disabled unless `ADMIN_PASSWORD` is set. Login compares SHA-256 digests in constant time, is limited to 5/min per IP, and issues an 8-hour typed admin token. The audit feed shows previews that are decrypted then redacted, or `[erased]`, so the dashboard reveals no direct identifiers.

- [WS-D — privacy layer + encrypted persistence + session/featu] **Rate limits, size limits, headers and CSP:** pure-ASGI middleware (not BaseHTTPMiddleware) so SSE streams unbuffered (tested). Strict CSP (`script-src 'self'`, `frame-ancestors 'none'`); a relaxed CSP only on `/docs` and `/redoc`. `nosniff`, `no-referrer`, `DENY` framing, Permissions-Policy, COOP, and `no-store` on `/api/*`. CORS limited to `CORS_ORIGINS` without credentials. Bodies over `MAX_REQUEST_BYTES` → 413; per-IP sliding windows → 429 with `Retry-After`. These are defence-in-depth layers outside the pipeline.

- [WS-D — privacy layer + encrypted persistence + session/featu] **Log scrubbing:** a structlog processor redacts PII from every string value (event text, nested values, formatted exceptions), bounded in size and depth, while secret-key masking is kept. The DB engine uses `hide_parameters=True` so SQL errors never carry bound values. Validation errors drop the `input` field before being logged or returned.

- [WS-D — privacy layer + encrypted persistence + session/featu] **Retention:** a background job (about 30 s after start, then hourly) crypto-shreds sessions inactive for more than `DATA_RETENTION_DAYS`, using exactly the user-initiated erasure path. It survives DB outages and stops on the lifespan stop event. This is data minimisation in the spirit of DPDP 2023 and HIPAA.

- [WS-D — privacy layer + encrypted persistence + session/featu] **Single-flush turn store:** `persist_turn(TurnRecord)` performs all reads first, then adds the events, snapshot upsert and soft-ask counter, both messages, one audit row (with trace) and the `last_active_at` update, then calls `db.flush()` exactly once (asserted in a test). The caller commits. This replaces the 5+ flushes per turn, while gate decisions and rationales are still logged in the immutable audit row. On regenerate, the stored state is left untouched.

- [WS-F corpus (knowledge-base expansion, manifest, ingestion u] ADL: curated corpus expansion from 3 to 27 documents. Decision: grow the knowledge base beyond the spec's 3-source rule, but only with authoritative, curated sources. These are clinical-society and government guidelines (AHA/ACC, ESC, ISH, WHO, KDIGO, NICE), society scientific statements and position papers, one CC BY review in a peer-reviewed journal, and US Government patient pages (MedlinePlus, NHLBI). Rationale: the system's scope (heart failure, atrial fibrillation, coronary disease, lipids, CKD, pregnancy, emergencies, lay questions) was unsupported by 3 hypertension PDFs. Safeguards against RAG poisoning: no PubMed or web scraping; a document is indexed only if listed in data/corpus_manifest.json with org, year, canonical URL, the publisher's licence and a SHA-256 pin; every chunk carries doc_sha256 so the index is versioned and auditable; licence restrictions are honoured (ADA 2026 excluded for its TDM prohibition). Architecture impact: none. Retrieval stays hybrid dense+sparse -> RRF(k=60) -> cross-encoder top-5, and both gates of the Dual Answerability Gate are unchanged. Gate 2 simply gets better evidence coverage, which lets it answer instead of generalising or abstaining where evidence now exists.

- [WS-F corpus (knowledge-base expansion, manifest, ingestion u] ADL: chunk size 400 tokens with 60 overlap, measured with the embedder's tokenizer. Previously chunks were 512 whitespace words with 64 overlap. - [I3 — Hinglish / Indian-English red-flag lexicon for the dete] ADL (next free number): Hinglish / Indian-English red-flag lexicon for the deterministic emergency fast path.

Context: Indian users describe emergencies in Roman-script Hindi mixed with English, e.g. 'seene mein dard', 'saans nahi aa rahi', 'lakwa maar gaya', 'bp bahut high hai 200'. The English-only rules missed all of these.

Decision: extend medbridge/core/emergency_classifier.py in place, keeping the same mechanism and no LLM:
- token-level canonicalisation of spelling variants (_HINGLISH_VARIANTS);
- 14 additional compiled rules with '_hi' ids (HINGLISH_RULE_IDS: chest_pain_hi, heart_attack_hi, breathlessness_hi, syncope_hi, stroke_face_hi, stroke_limb_hi, stroke_speech_hi, stroke_vision_hi, stroke_self_report_hi, severe_headache_hi, hemoptysis_hi, hematemesis_hi, self_harm_hi, seizure_hi);
- a post-position negation scope for Hindi 'nahi' (allow-listed gap, closing follower, aur/ya list walk bounded at 4 items, a void phrase, re-affirmation), plus 'na to X na Y';
- Hindi wording for the informational, personal, historical, recency, exertion and BP-threshold filters.
Every Hinglish pattern needs a Hindi word or an Indian-English idiom, so English behaviour does not change.

When unsure, the rules escalate (pseudo-negations such as 'nahi ja raha' / 'kam nahi ho raha' do not negate; a BP crisis is never negated).

Consequences:
- English outputs are identical on 3,951 test strings.
- 2,000-character median latency +0.5 ms (1.19 → 1.69 ms), still under 5 ms.
- 100% branch coverage kept.
- Development-set precision and recall are 1.000 on 141 synthetic Hinglish cases (90 positives, 51 negatives).
- Known false positives are listed in the report.

Provenance: the lexicon and case file were developed WITHOUT access to the HalluBench test items (evaluation/datasets/hallubench_v1.json and HALLUBENCH.md were not opened).
