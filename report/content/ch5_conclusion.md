# Conclusion and Future Work

## Summary of Work Completed

The project set out to build a conversational assistant for hypertension and cardiovascular care that decides, before writing any clinical text, whether it is entitled to answer. MedBridge implements this as a Dual Answerability Gate inside the approved eight-step pipeline. The architecture and its invariants were kept while the orchestrator was rewritten as traced stage methods with a single database flush, speculative retrieval, citation validation, small-talk handling and correct multi-turn follow-ups, with every change justified in the Architecture Decision Log. The emergency fast-path became a deterministic natural-language rules engine covering colloquial, negated, misspelt and Hinglish phrasing within 10 ms. The corpus grew from 3 to {{corpus.totals.documents|int}} curated documents with a checksummed manifest and tokenizer-measured chunking, and the fusion constant was corrected to 60. All inference runs locally with grammar-constrained outputs, and two variants, a calibrated Evidence Gate (V1) and a grounding verifier (V2), were added. The Review-1 limitations of deferred PII anonymisation and missing authentication were removed through redaction before any model call and signed session tokens, together with per-session encryption, crypto-shredding erasure and security middleware. A chat interface with streamed progress, citations and a "Why this answer?" panel replaced Streamlit. Finally, MedBridge-HalluBench and an evaluation package with nine conditions, two judges, development-only calibration, degraded-turn accounting and paired statistics were built, the AQ, RABBITS, adversarial, smoke and load harnesses were made live, and an adversarial code review confirmed and fixed 37 defects before the final experiments.

## Conclusion

This project showed that the decision of whether to answer can be made an explicit, auditable part of a retrieval-augmented medical assistant. MedBridge separates the two reasons for holding back, insufficient patient context and insufficient evidence, into two gates at two points of the pipeline, places a deterministic emergency check in front of both, and routes every message to one of five actions whose provenance is recorded in an immutable audit log and shown to the user. The complete system runs on a single laptop with free, locally hosted models and sends no patient text to any external service.

The component evaluations support several design choices and expose clear limits. Grammar-constrained decoding made the output of small local models reliably parseable, so routing quality, not malformed output, distinguishes candidate models. Hybrid retrieval gave the best ranking metrics, well ahead of sparse retrieval in the point estimates (the intervals barely overlap) and slightly ahead of dense retrieval (the intervals overlap widely), while the reranker did not measurably improve ranking and is retained mainly as an evidence-sufficiency signal. Rule-based redaction proved precise and safe for clinical values but recalled only part of the personal names in a blind test.

## Limitations and Future Enhancements

The limitations are discussed at the end of Chapter 4. The following enhancements address them.

1. **Complete the knowledge base.** Obtain the missing heart-failure, ESH, chronic coronary disease and ESC atrial fibrillation guidelines through a browser download or institutional access, resolve the licence questions, re-ingest new versions automatically through the manifest, and name each source when guidelines disagree.
2. **Clinician-validated benchmark and stronger evaluation.** Have clinicians review the HalluBench labels with inter-annotator agreement, add multi-turn, Hinglish and regional-language items, complete the human annotation sheet, use a panel of judges or a larger judge with one claim per call, and repeat the study on both target machines.
3. **Better-calibrated abstention.** Add a conformal or selective-prediction threshold on gate confidence so that abstention can be set to a target risk level [@angelopoulos2023conformal], and evaluate the MedCPT cross-encoder, which was not significantly better than the default in Table 4.4, as the V1 evidence signal.
4. **Grounding verification and real streaming.** If V2 performs well once calibrated, enable it by default with explicit checks of numbers and drug names, and stream generator output with sentence-level validation so that the first words appear within seconds while no unvalidated claim reaches the patient.
5. **Stronger privacy.** Add a local named-entity model or gazetteer for names without a cue, more international identifier formats, master-key rotation, token revocation and storage of the master key in the operating system's key store.
6. **Multilingual use, deployment and studies.** Extend understanding to Hindi, Tamil and Hinglish questions; verify installation, performance and accessibility on the Windows target laptop; support several workers with a shared rate limiter; import readings from home BP monitors; and run a usability study under ethics approval, with a prospective clinical evaluation before any real-world use.
